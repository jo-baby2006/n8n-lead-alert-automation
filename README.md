# Lead Form to Multi-Channel Alert System (n8n)

## Overview
An n8n workflow that receives a lead form submission through a webhook, cleans the data, and then sends two notifications from the same execution:
1. An internal alert to a Discord channel
2. An automatic confirmation email to the customer through Gmail

```
Receive Lead Submission -> Format Lead Fields -> +-> Send Internal Discord Alert
                                                 +-> Send Customer Confirmation Email
```

## Nodes
| Node name | Type | Purpose |
|---|---|---|
| Receive Lead Submission | Webhook (POST, path `form-submission`) | Receives the JSON payload from the form (tested with Hoppscotch) |
| Format Lead Fields | Edit Fields (Set) | Trims values, maps keys, adds a timestamp |
| Send Internal Discord Alert | Discord | Posts a Markdown-formatted alert to the team channel |
| Send Customer Confirmation Email | Gmail | Sends the confirmation email to the lead |

Both outgoing nodes are connected to the output of `Format Lead Fields`, so a single submission triggers both in the same execution and neither depends on the other.

## How the webhook payload was tested
Tool used: Hoppscotch (POST request, `Content-Type: application/json`).

Sample payload:

```json
{
  "fullName": "Jane Doe",
  "email": "jane.doe@example.com",
  "company": "Acme Corp",
  "query": "Inquiring about bulk enterprise pricing."
}
```

Equivalent cURL command (replace the URL with your n8n webhook URL):

```bash
curl -X POST "https://YOUR-N8N-HOST/webhook-test/form-submission" \
  -H "Content-Type: application/json" \
  -d '{"fullName":"Jane Doe","email":"jane.doe@example.com","company":"Acme Corp","query":"Inquiring about bulk enterprise pricing."}'
```

During testing the workflow was run with **Execute workflow** and the request was sent to the Test URL. After publishing, the Production URL (`/webhook/...`) is used.

## Data transformation (Format Lead Fields)
| Output key | Source | Rule |
|---|---|---|
| lead_name | fullName | whitespace trimmed |
| lead_email | email | whitespace trimmed |
| lead_company | company | whitespace trimmed, falls back to "Not provided" if empty |
| lead_message | query | whitespace trimmed |
| received_at | n/a | ISO 8601 timestamp generated at execution time |

## Message formats
**Discord message:** a bold header "🚨 New Lead Received", then name, email and company in bold labels, the message as a quote (`>`), and a localized date and time.

**Customer email:**
- Subject: `We received your inquiry, {{lead_name}}`
- Body: greeting with the lead's name, confirmation of the specific query received, and a follow-up promise of 24-48 business hours.

## Assumptions
- The sender posts JSON, so the fields arrive under the webhook's `body` object.
- Required fields (name, email, query) are always supplied by the form.
- Timestamp is generated by n8n at the time the webhook is received.
- The follow-up window is stated as 24-48 business hours.
- Credentials (Discord, Gmail) are not included in the export and must be reconnected after import.

## Edge cases identified
- **Missing optional fields:** If `company` is empty, Format Lead Fields uses "Not provided". Missing text fields default to an empty string (`?? ''`) so `undefined` never appears in messages.
- **Malformed email:** The workflow does not validate the email format. Gmail would fail on an invalid address. An IF node with a regex check could route invalid emails to Discord only.
- **Branch failure:** If one notification node fails, the other should still run. Setting On Error to "Continue (regular output)" on both nodes keeps them independent.
- **Multi-line messages:** Line breaks in the query need quote markers on each line in Discord so the whole message stays in the blockquote.
- **Markdown characters in input:** Characters like `*`, `_` or `` ` `` in the message can change Discord formatting and may need escaping.
- **Duplicate or spam submissions:** No de-duplication or rate limiting is applied.
